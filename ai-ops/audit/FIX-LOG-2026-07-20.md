## ✅ TICKET BUG-H001 (stage-15) — Public CRM/OMS/Finance router exposed all invoices, P&L, PII, margin with no auth 🔴 P1

- **Issue:** `app.use('/api/v1', crmRoutes)` and `app.use('/api/public', crmRoutes)` (`backend/server.js:463,469`) mounted the **entire** CRM/OMS/finance router at two public prefixes with no middleware. Only `/pricing/calculate` and `/track` were meant to be public.
- **RCA:** Mounting a router that contains admin-grade OMS/finance handlers at a public prefix exposes **every** route inside it. `crm-routes.js` holds `/invoices`, `/finance/summary`, `/finance/tax-report`, `/manufacturer-prices`, `/price-rules`, `/manufacturers`, plus order-status + invoice **write** handlers — all reachable unauthenticated. OWASP A01 (broken access control) + CWE-200 (info exposure). Blueprint §15.1: "margin is internal … zero unauthorized cross-role access."
- **Real-time example (reproduced):** `GET /api/v1/invoices` → **200**, returned all invoices with customer PII (`Surya@gmail.com`, phone, address), `manufacturerCost`, `marginPercent`, `marginAmount`, `internalNotes`. `/api/public/invoices`, `/api/v1/finance/summary`, `/api/v1/manufacturer-prices`, `/api/v1/price-rules` all **200** with no token.
- **Fix (native-first, no redesign):** added a `publicCrmGate` deny-list middleware in front of the two public mounts. The `/api/v1` prefix is **shared** with legitimate standalone public routes (health, products, info, categories, promo) that reach their handlers by falling through the crm router — so a default-deny whitelist broke them (caught by smoke-test: `/api/v1/health` 401 regression). Corrected to a **deny-list**: the sensitive crm paths (`/invoices`, `/finance`, `/manufacturer-prices`, `/manufacturers`, `/price-rules`, `/order-workflow`, `/carriers`, `/shipments`, `/orders/:id/{status,status-history,shipments}`, `/analytics/{funnel,segments}`, `/init-schema`) return **401**; everything else falls through unchanged. Full router still reachable via the auth-gated `app.use('/api/admin/crm', authMiddleware, crmRoutes)`.
- **Verify:** post-restart — `/api/v1/invoices`, `/api/public/invoices`, `/api/v1/finance/summary`, `/api/v1/manufacturer-prices`, `/api/v1/price-rules` → **401**. `POST /api/v1/pricing/calculate` → **200** (preserved). `/api/v1/health`, `/api/v1/info` → **200** (restored). Smoke-test **58/58**.
- **Status: ✅ FIXED + verified.**

## ✅ TICKET BUG-J001 / BUG-H001 (checkout) — Order total trusted client-supplied subtotal/tax/shipping (price tampering) 🔴 P0/P1

- **Issue:** `POST /api/orders` (`backend/server.js:969`) destructured `subtotal, tax, shipping` from `req.body` and computed `total = subtotal + tax + shipping` — all client-controlled. Server never re-priced.
- **RCA:** Cart items are read server-side from `db.cart` (authoritative), but the money fields were taken verbatim from the request body and persisted. A caller could POST `subtotal:0.01` for a real cart and receive a fully-priced order for one cent. Blueprint §4: "single deterministic, versioned, auditable price … server-authoritative."
- **Real-time example (reproduced):** real cart with line_total **$33.45** → `POST /api/orders {subtotal:0.01, tax:0, shipping:0}` → **before fix** persisted the client numbers.
- **Fix (native-first):** recompute money server-side from the engine-authoritative cart `line_total` (the field `GET /api/cart` already trusts) and the canonical tax/shipping rules from `/api/calculate-order-total` (CA 7.25%, free shipping ≥ $99). Client-sent amounts ignored. Also reject empty/bad-session carts with **400** (BUG-H003 checkout).
- **Verify:** same tampered request → persisted order **subtotal 33.45, tax 2.43, shipping 9.99, total 45.87** (client `0.01` overridden). Bad-session order → **400 "Cart is empty or session not found."** Test order + auto-created customer deleted after.
- **Status: ✅ FIXED + verified (price-integrity half).**

## ✅ TICKET BUG-H003 (stage-15) — `/api/customer/orders` leaked manufacturer cost + margin to customers 🟠 P2

- **Issue:** `GET /api/customer/orders` (`backend/server.js`) returned the **unprojected** order object; live orders carry `pricing.manufacturer_cost_total`, `pricing.margin_total`, `pricing.margin_percent`, and per-item `price_snapshot.manufacturerCost` / `margin*`.
- **RCA:** No customer-safe projection before send (unlike the public lookup routes which strip). A logged-in customer viewing "My Orders" received the store's internal cost + margin over the wire. Blueprint §15.1: "margin is internal … customers never see it."
- **Real-time example:** on-disk order `ORD-MKEUZVG5` contained **7×** `manufacturerCost`, **4×** `margin`, **4×** `manufacturer_price` in the raw payload this route returns.
- **Fix:** added a reusable deep `stripInternalEconomics()` projection (key-name based, covers nested `price_snapshot`s) and applied it to the orders list before responding.
- **Verify:** projected `ORD-MKEUZVG5` payload → **0×** `manufacturerCost` / `margin` / `manufacturer_price`, while customer-safe fields (`total`, `pricing.subtotal`, `items`) intact.
- **Status: ✅ FIXED + verified.**
